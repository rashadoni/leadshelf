# Самокритика, улучшения и UX-видение (2026-07-02)

Честный разбор текущего состояния проекта (docs + schema v0 + план миграции)
и идеи, которые делают LeadShelf лучшим в классе по UX.

## Часть 1. Самокритика

### 1.1 Стратегический риск: двойное позиционирование

Расширение scope до full MTM (docs/08) — решение владельца, оно принято. Но
надо честно назвать цену: LeadShelf теперь конкурирует одновременно с Leafio
(планограммы) и с SFA-системами (маршруты/заказы). Оригинальные docs и Codex
предупреждают об одном и том же: field-force и заказы могут похоронить
планограммный MVP. Дисциплина: позвоночник «планограмма → publish → фото»
всегда приоритетнее полей/заказов при конфликте ресурсов.

### 1.2 Документация противоречива

- `docs/01` до сих пор говорит «маршруты только если нужны, не главный модуль»
  и не включает заказы; `docs/03` roadmap не имеет фаз для routes/visits/orders;
  `docs/04` запрещает «тащить весь MTM sidebar». Всё это противоречит `docs/08`.
- Нужно: пройтись по 01/03/04 и синхронизировать с 08 (roadmap получает фазы
  field-force после Phase 6).

### 1.3 Ошибки в schema v0 (найдены при само-ревью)

1. **Сломан immutable publish (самое серьёзное).**
   `PlanogramPlacement.shelfId → EquipmentShelf`, а полка принадлежит
   `EquipmentTemplate`. Изменение шаблона (сдвинуть полку, поменять глубину)
   задним числом меняет ОПУБЛИКОВАННЫЕ планограммы — ровно то, что docs/04
   запрещает. Fix: вернуть `EquipmentVersion` из docs/07 (publish замораживает
   версию геометрии) или копировать геометрию полок в `PlanogramEquipment`
   при публикации.
2. **Cascade-delete стирает историю.** Все снапшоты (`PriceSnapshot`,
   `StockSnapshot`, `SalesSnapshot`) имеют `onDelete: Cascade` от Product —
   удаление товара уничтожает историю продаж и ломает отчёты за прошлые
   периоды. Fix: `onDelete: Restrict` + деактивация вместо удаления.
3. **NULL в unique-констрейнтах снапшотов.** `@@unique([productId, storeId,
   date])` с nullable `storeId`: в Postgres NULL != NULL, значит org-wide
   снапшоты дублируются. Fix: partial unique indexes в SQL-миграции или
   sentinel-значение.
4. **Строковые ссылки без FK**: `Task.assigneeId`, `AuditLog.userId`,
   `Team.leadUserId`, `*.byUserId` — теряется целостность. Осознанный
   компромисс v0, но `Task.assigneeId` точно должен стать FK.
5. **Нет ассортиментной матрицы по формату.** Оставил только `StoreAssortment`;
   для сети из 100 аптек управлять ассортиментом по-точечно — боль. Матрица
   формата — ключ к масштабированию (docs/07 её имел, я урезал).
6. **Нет связи «планограмма → место на плане зала».** Phase 6 обещает
   мобильному «floor plan location hint», но `PlanogramAssignment` и
   `FloorPlanEquipment` не связаны — флоу «куда подойти» нереализуем.
7. **Единицы измерения.** `Product.unit @default("pcs")`, а canonical-значения
   MTM — «шт/ящик/кг/л/пачка». При импорте 1С будет каша. Нужен единый
   словарь единиц + маппинг при импорте.
8. **Нет i18n-стратегии.** Продукт для Азербайджана (MTM-сайдбар на
   азербайджанском!), MTM локализован az/ru. В schema нет языковых полей, в
   плане нет i18n. Решить сразу: UI-локализация через messages (az/ru/en),
   данные — на языке тенанта.

## Часть 2. UX/UI-видение: чем LeadShelf побеждает

Принцип: Leafio и конкуренты — «рисовалки с отчётами». LeadShelf должен быть
**редактором, где каждое действие информировано деньгами, и мобильным
исполнением, которому доверяют без сети**.

### Tier 1 — дифференциаторы MVP (строить сразу)

1. **Деньги в drag-preview.** Тянешь товар на полку — в превью живые данные:
   ABC-класс, оборот/день, дней запаса, доля полки после размещения.
   Категорийный менеджер принимает решение в момент движения руки, а не
   после экспорта в Excel.
2. **Diff-режим версий («git diff для полки»).** Overlay/side-by-side двух
   версий: added/removed/moved подсветка + дельта метрик (линейные метры по
   брендам, прогноз оборота). Закрывает главную боль согласования: «что
   изменилось и зачем».
3. **Валидация как физика, не как ошибка.** Невлезающий товар не краснеет
   после сохранения — он физически не встаёт: ghost + причина («глубина
   320 мм > полка 300 мм»). Математика уже есть в `packages/core/capacity`.
4. **Offline-доверие как UX.** Явная очередь: «3 фото и 1 отчёт в очереди,
   отправятся при сети», с ручным retry. Полевые сотрудники бросают
   приложения, которым не верят, — статус синка должен быть виден всегда.
5. **Камера-оверлей на мобильном.** Полупрозрачная планограмма поверх
   видоискателя при фото-подтверждении: сотрудник сверяет выкладку глазами,
   без AI. Дёшево, вау-эффект, и заодно дисциплинирует ракурс фото — готовые
   данные для Phase 10 (golden reference).

### Tier 2 — fast-follow (сразу после MVP)

6. **Рентген-слои** (как слои в Figma): heatmap продаж, наценка, дни запаса,
   бренд-блоки — переключение клавишами 1/2/3/4 поверх полки.
7. **Explainable autofill с таймлайном.** Слайдер по шагам алгоритма
   автозаполнения; каждый товар кликабелен: «здесь, потому что правило X,
   сортировка ABC; не влезли Y, Z». Требование docs/03 Phase 5, поднятое
   до UX-фичи.
8. **Cmd+K палитра** + omnisearch: SKU/планограмма/точка/задача/действие
   («опубликовать на формат Стандарт»).
9. **Комменты-пины на полке** (как в Figma): согласование планограммы внутри
   продукта, а не скриншотами в WhatsApp.
10. **Сканер-навигатор в мобильном**: скан штрих-кода → «стеллаж 3, полка 2,
    4 фейса» + точка на плане зала (требует fix 1.3.6).
11. **Сегментный чек-лист выкладки**: полка разбита на зоны, прогресс и фото
    по сегментам — вместо «одно фото на всю стену».

### Tier 3 — v1.5+ (информативность и приятность)

12. **QR-паспорт полки**: наклейка на стеллаже → текущая планограмма, история
    версий, метрики этой полки. Физический мир ссылается на цифровой.
13. **Утренний дайджест** офису (push/email): выполнено/просрочено вчера,
    аномалии визитов, топ-3 проблемы данных.
14. **Печатный режим планограммы** (PDF: полка + таблица + чек-лист) — аптеки
    реально печатают; экспорт должен быть красивым, это касание бренда.
15. **NL-запросы к данным** («покажи SKU без габаритов в Витаминах») — 
    LLM-фича, которая дешевле и раньше computer vision.
16. **Голосовые комментарии** с транскрипцией в мобильном — руки заняты
    товаром.

### Анти-идеи (не делать, hype-ловушки)

- AR-наложение через ARKit/очки — дорого, хрупко, камера-оверлей (№5) даёт
  80% ценности за 5% цены.
- 3D-first редактор — docs/02 прав, 3D только viewer.
- AI-first compliance до стабильного фото-потока — docs/05 прав.
