# LeadShelf: Guided Capture assistant (гид съемки в объективе)

Обновлено: 2026-07-07. Статус: план, реализация не начата.

Документ развивает `docs/23-guided-shelf-proof-plan.md`. Там зафиксирован
обязательный сценарий шагов (front/left/right/detail); здесь — как система
ведет мерчендайзера внутри каждого шага: подсказки прямо в видоискателе,
как при сканировании банковской карты, но с большей функциональностью.

Проблема, которую решаем: post-capture quality gate ловит плохой кадр после
съемки и заставляет переснимать. Гид должен предотвращать плохой кадр до
нажатия затвора: рамка, наклон, свет, композиция — в реальном времени.

## Принципы

- Гид помогает, но никогда не блокирует. Если за N секунд рамка «почти
  сошлась», разрешается ручной снимок со статусом `accepted_with_warnings`.
  Худший исход — агент, который не может отправить proof — недопустим.
- Photo-first. Обязательные шаги сценария — фото (burst-серия), а не видео.
  Это возврат к исходной рекомендации docs/23 («начать с фото по шагам»).
  Видео — опциональный аудит-артефакт, догружается лениво по WiFi.
- Все подсказки уровней 1-2 работают полностью офлайн. Серверные подсказки
  уровня 3 — только enhancement, никогда не условие отправки.
- Силуэт и правила съемки берутся из физической модели оборудования (мм),
  а не из generic-прямоугольника. Это использование уже существующей
  equipment library (Phase 2) и главное отличие от конкурентов.
- Гид не делает плохой кадр хорошим и не подменяет честные статусы; он
  снижает долю плохих кадров и время агента.

## Уровень 1 - без нативных модулей (текущий Expo stack)

- Силуэт оборудования в видоискателе: аспект и разбивка по полкам берутся
  из geometry шаблона оборудования (widthMm/heightMm/полки).
- Гироскоп: пузырьковый уровень; допуск наклона задается шаблоном шага
  (front — вертикально, depth — наклон/композиция, см. ниже).
- Одна инструкция на экран: короткий текст + пиктограмма, RU/AZ.
- Вибрация, когда телефон выровнен по гироскопу.
- Съемка burst (3 кадра) по кнопке; локальный post-capture отбор лучшего:
  резкость (Laplacian variance), яркость (гистограмма). Немедленный совет
  «пересними: темно/смазано», пока агент у полки.
- Люк «оборудование не совпадает»: фото как есть + `equipment_mismatch`
  флаг в офис. Побочная ценность — полевая ревизия базы оборудования.
- `manual_exception` с причиной, если шаг физически невозможен
  (перекликается с backlog docs/23).

## Уровень 1.5 - серверное выпрямление и мм-калибровка

Не требует нативного кода; выполняется worker-ом после загрузки.

- Детекция ребер полки на кадре, homography -> выпрямленный «скан» полки
  (как сканер документов разворачивает страницу).
- Масштаб мм/пиксель из известной ширины оборудования. После этого зоны
  планограммы накладываются на фото напрямую, в тех же миллиметрах, и
  фактическая ширина выкладки измерима в мм, а не «на глазок».
- Выравнивание кадров одной точки между визитами -> честный diff
  «что изменилось на полке» (возможен только благодаря guided-съемке).
- Учет линзы: EXIF focal length/зум обязателен в metadata; wide 0.5x дает
  бочкообразную дисторсию, которая ломает мм-измерения по краям — либо
  коррекция, либо запрет wide в шаблоне шага.
- Face blur покупателей при ingestion, до записи в постоянное хранилище.
  Честно: blur на устройстве требует нативных frame processors, поэтому
  первый срез — серверный blur до персистентности; on-device — уровень 2+.

## Уровень 2 - live-гид (react-native-vision-camera)

Требует dev-client/prebuild и отдельного technical spike: текущий стек —
Expo Camera v57 без frame processors.

- Live-детекция прямоугольника/ребер полки: рамка красная, пока ракурс
  неправильный, зеленая — когда полка села в силуэт.
- Автозатвор: стабильная зеленая рамка -> автоматическая burst-серия ->
  выбор самого резкого кадра. Агент не жмет кнопку вообще.
- Select-then-upload: на сервер уходят 3-5 лучших JPEG, а не видео;
  оригиналы/видео — лениво по WiFi только для аудита.
- Live-детекция блика на стекле («сдвинься левее»), смаза и темноты.

## Уровень 3 - AI-гид, голос, AR

- Легкая on-device модель (полка/холодильник/зона): стрелки «левый край
  не влез», «отойди на шаг».
- Голосовые подсказки TTS RU/AZ: агент не читает экран на вытянутой руке.
- Server-assisted мгновенный вердикт после кадра (retake hint за секунды),
  только при наличии сети.
- AR-«призрак» планограммы поверх камеры: агент видит ожидаемую выкладку
  на фоне фактической. Требует уровня 1.5 (rectification + calibration);
  это апогей in-visit correction loop, не блокер ранних срезов.

## CaptureTemplate

Шаги сценария определяются типом оборудования и задачей, не хардкодом.

Поля шага (минимум): `stepKind`, `required`, источник силуэта (equipment
geometry), допуск наклона, минимальная яркость, composition hint,
`doorPolicy` для холодильников («дверь можно/нельзя открывать» — политика
сети), `depthMode`, флаг разрешения wide-линзы.

`depthMode` — режим проверки глубины по типу клиента (см. docs/25):

- `angle_photo`: фото под углом слева/справа; для открытых холодильников —
  кадр сверху при открытой двери.
- `manual_attestation`: агент физически проверяет задний ряд (его прямая
  обязанность при ротации), кнопка «второй ряд есть/пусто» + close-up фото
  зазора. Выборочный аудит офисом.
- `stock_triangulation`: сверка facings на фото с остатками из 1С
  (доступно только клиентам-сетям со своим master-data).

Узкие проходы и высокие стеллажи: полка не влезает в кадр — сегментная
съемка 2-3 перекрывающихся кадров по зонам планограммы. Автосклейку панорам
не делаем: артефакты на швах дублируют/съедают товары и ломают подсчет
facings; AI и так анализирует по зонам.

## Телеметрия гида

С первого среза логируем: время до принятого кадра по шагу, число
пересъемок, долю ручных override, шаблоны, где рамка «не сходится».
Это объективная метрика полевого трения и автодетектор кривых шаблонов
(«этот холодильник все снимают по 2 минуты — шаблон неправильный»).
Телеметрия же дает данные для тюнинга порогов quality gate после пилота.

## Подводные камни (зафиксированы осознанно)

- Гид не имеет права блокировать отправку — только маркировать качество.
- Батарея/нагрев: CV на превью активен только внутри шага съемки, не весь
  визит; у агента 8 часов и 15 точек.
- Зоопарк Android: слабые устройства и кривые гироскопы -> деградация до
  статичной рамки; feature detection, не предположения.
- Стекло холодильников: блики; `doorPolicy` в шаблоне, детекция блика и
  совет сместиться — вместо нерешаемой «коррекции» блика.
- Угловые depth-кадры нельзя вести гироскопом (он знает наклон к земле, а
  не к полке) — ведем композицией: «правый край полки у левого края кадра».
- Dev-режим: разработка гида по фото полок на мониторе будет блокироваться
  нашим же антифродом (детекция экрана) — нужен явный dev-флаг.
- Пороги (резкость/яркость/наклон) не хардкодить навсегда: калибровка по
  телеметрии и пилотным данным.

## Implementation slices

### Срез 1 - уровень 1, без нативки

1. `CaptureTemplate`: schema + API + seed-шаблоны «стеллаж» и «холодильник».
2. Wizard UI: силуэт из geometry, гироскоп-уровень, вибрация, одна
   инструкция на экран.
3. Photo-first: обязательные шаги переводятся на burst-фото с локальным
   отбором лучшего кадра; видео становится optional/lazy (WiFi).
4. Люк `equipment_mismatch` + `manual_exception` с причиной.
5. Базовая телеметрия шагов.

DoD среза 1:

- Агент проходит сценарий с гидом полностью офлайн.
- Каждый кадр знает свой template/step и несет lens/gyro metadata.
- Плохой кадр получает немедленный локальный совет пересъемки.
- Mismatch/exception доходят до офиса как события, не теряются.
- Тесты: отбор кадра из burst, quality check, template resolution.

### Срез 2 - уровень 1.5, серверный

1. Rectification worker: детекция ребер, homography, rectified-копия рядом
   с оригиналом.
2. Масштаб мм/px + наложение зон планограммы на фото в `/reviews`.
3. Face blur при ingestion до постоянного хранения.
4. Базовое выравнивание кадров между визитами (фундамент diff).

DoD среза 2: ревьюер видит зоны планограммы поверх выпрямленного фото;
мм-ширина зоны отображается рядом с нормативом; лица заблюрены в хранимых
копиях; тесты на homography/scale по синтетическому кадру.

### Срез 3 - уровень 2, native spike

Spike `react-native-vision-camera` + frame processors (dev-client build),
затем live-рамка, автозатвор, select-then-upload, live glare/blur.

### Срез 4 - уровень 3

Голос TTS, server-assisted retake hints, AR-призрак планограммы.

## Что сознательно не делаем сейчас

- Автосклейка панорам.
- Обучение собственного детектора до подтверждения ценности пилотом.
- AR до готовности rectification/calibration.
- On-device нейронки до среза 3.
